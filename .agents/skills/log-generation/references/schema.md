# Log Schema and Redaction

## Required Fields

- timestamp: ISO-8601 or epoch millis
- level: DEBUG, INFO, WARN, ERROR
- message: short human summary
- service: service or app name
- env: local, dev, staging, prod

## Strongly Recommended Fields

- request_id: per-request ID
- trace_id: distributed trace ID
- span_id: span ID when tracing is enabled
- route: route or handler name
- method: HTTP method
- status_code: HTTP status
- latency_ms: request duration
- error: error message or error type
- stack: stack trace for errors

## Log Generation Entry Format

Use this format for entries generated by the log-plan script or manual planning.

```json
{
  "event": "http_request",
  "level": "INFO",
  "message": "HTTP request",
  "service": "service-name",
  "required_fields": ["timestamp", "level", "message", "service", "env"],
  "recommended_fields": ["request_id", "trace_id", "span_id", "route", "method", "status_code", "latency_ms"],
  "template": {
    "timestamp": "<auto>",
    "level": "INFO",
    "message": "HTTP request",
    "service": "service-name",
    "env": "${ENV}",
    "event": "http_request",
    "request_id": "${request_id}",
    "trace_id": "${trace_id}",
    "span_id": "${span_id}",
    "route": "${route}",
    "method": "${method}",
    "status_code": "${status_code}",
    "latency_ms": "${latency_ms}"
  }
}
```

## Redaction Rules

- Never log secrets, tokens, passwords, or auth headers.
- Avoid logging PII. If unavoidable, log a stable hash or partial mask.
- Use allowlists for structured fields and explicitly drop or mask unknown keys.

## Level Guidelines

- DEBUG: verbose diagnostics for local use
- INFO: lifecycle events, successful requests
- WARN: unexpected states, retries, timeouts
- ERROR: failures with context and stack
