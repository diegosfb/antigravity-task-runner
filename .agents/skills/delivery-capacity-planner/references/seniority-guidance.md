# Seniority guidance

Use five bands when possible: Junior, Mid, Senior, Lead/Principal, Architect/Expert.

Evaluate:
1. Whether juniors/mids have enough senior supervision.
2. Whether senior people are doing work that can be delegated.
3. Whether each pod has credible technical ownership.
4. Whether scarce expertise is concentrated in one person.
5. Whether the pyramid matches ambiguity: discovery and modernization need more seniority than repeatable execution.
6. Whether ramping many new hires simultaneously requires temporarily higher senior coverage.

Default diagnostic starting point for ordinary software delivery when no better evidence exists: roughly 10-20% junior, 35-50% mid, 30-40% senior, and 5-15% lead/principal/architect. Do not present this as a company standard. Adjust materially for context and explain why.
