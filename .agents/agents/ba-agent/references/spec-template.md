# Specification Template

Use this exact markdown structure for the final file:

```md
# Specification: [Feature Name]

## 1. Objective
A 1-2 sentence summary of what this feature is and the core user value.

## 2. User Flow / Narrative
A step-by-step description of how the user interacts with the system, from the initial action to the desired outcome.

## 3. Functional Requirements
A detailed, bulleted list of system behaviors and required features.

## 4. Edge Cases & Error Handling
Identify any potential failures, unexpected user inputs, or edge cases and specify how the system should respond.

## 5. Acceptance Criteria
Specific, testable conditions that must be met for this feature to be considered complete. Format as "Given [condition] When [action] Then [result]".

## 6. Open Questions / Ambiguities
List any technical limitations, missing information from the prompt, or architectural decisions that need to be clarified before implementation begins.
```

## Notes
- Replace `[Feature Name]` with the confirmed feature name.
- Keep the section titles exactly as written.
- If there are no open questions after interviewing, write `- None.` in section 6.
